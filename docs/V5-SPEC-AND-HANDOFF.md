## 2. What the three reference sites actually do (measured by Dave in a real browser, 1440x900)

- **abatable.com**: GSAP + ScrollTrigger + Lenis. The hero is `position: sticky` (`hero_home_sticky`, 900px tall) and stays put for well over 1500px of scroll while contour lines grow, an orange dashed line draws and the headline reveals word by word. Scrolling changes `scrollY` (200 at 2 ticks, 500 at 5) but nothing in the hero moves. So: **pin + scroll-scrubbed drawing**, not scroll-jacking. We copy the idea (sticky pin, scrubbed branch), not their code.
- **jjettas.com**: Lenis. A sticky pane (`jj-pin-pane`, 900px) turns vertical wheel into a horizontal card track; cards are staggered in height and run off the right edge. A custom cursor label ("WATCH") follows the pointer.
- **edolus.com**: PlayCanvas (WebGL) + GSAP, a custom cursor orbit ring. In headless Chrome it never got past the loading splash (80% to 95% in 5s), so Dave could NOT see the intro web. "Interactive and moving" is read from Haaija's words: idle motion plus reaction to the pointer. If he means something more specific he should say or send a screen recording.

## 3. Architecture (decisions)

1. **Pin without moving the markup.** `<header>` is wrapped in `div.pin-a` (height header + P, margin-bottom -P, header `position: sticky; top: 0`), the hero section in `div.pin-b` (height hero + P, hero `position: sticky; top: var(--hdr)`). Both release at the same scroll position (P). `--pin` (px) is set by JS; without JS it is 0 and the page is identical to v4. Pin is off when the hero is taller than the viewport (phones, short screens), when reduced motion is on, or when printing. Header stays before `<main>` and the hero stays inside it, so landmarks are unchanged.
2. **Two router runs.** (a) *Intro* run inside the pinned hero: roots = the hero web's Tracker/Calendar/Email dots (stems), blocks = hero text and labels, target = bottom edge. Drawn in an svg inside the hero; its progress is `p = scroll / P`, scaled so the main route completes exactly at P. (b) *Page* run below the hero seam: root = the seam point, blocks = everything below. Both use `weave-grow.js`'s `grow()`. In flow mode (no pin) the intro svg is driven by `scroll / (0.55 * viewport height)` instead.
3. **Intertwining.** List-like containers (`.ptable, .step, .proof, .assure`) are no longer blocked as boxes, only their text is, so threads can pass along dividers and through gaps. Containers with graphics or inputs (`.canvas-demo, .week, .contact-card, .wx-stage`) stay blocked. New targets: each Thread bead (short connector), a right-gutter point per section (forces content crossings), and the tool web's node dots (R4). Router change: export a clearance map so motion can be limited near text.
4. **Tool web = big, in document flow, not sticky** (so threads can attach to it). Nodes are the hero web's layout stretched to the section width. The stage becomes a popup positioned by a pure `place()` function (side with room, centred on the node, clamped inside the field). A transparent bridge covers the gap so the pointer never leaves hover. On narrow screens (<= 760px) the popup is a normal block under the web (v4 layout).
5. **Wheel to sideways** on the whole popup: dominant axis delta -> smoothed `scrollLeft` target; `preventDefault` only while it can still move in that direction; 250ms hold at the ends so an overshoot does not drag the page; ctrl+wheel and horizontal trackpad deltas pass through.
6. **Alive layer.** Idle drift (one smooth field of x, y, t, so connected branches stay connected), pointer silk (displacement scaled by distance to the pointer AND by free space around that point, so a thread can never be pushed into text), nodes lean, signal dots travel along visible branches. Everything stops when the tab is hidden or reduced motion is on.
7. **Budget.** v4 was 41,789 B gzipped against 40,960 B. v5 ships `dist/` minified with esbuild (`tools/build_dist.js`); the budget is measured on `dist/`.

## 5. Pitfalls learned the hard way (do not repeat)

- A "0 collisions" result on a web that did not draw is meaningless. Always require a live web (thousands of samples, reaches Contact) AND run a negative control.
- Silent output is not a pass (a test runner that printed nothing exited 0). Print an explicit "passed" line.
- A fixed 10px routing grid misses 5px gaps depending on viewport width; the cell is 5px under 480px.
- Call `Page.bringToFront` before every browser check; reset device emulation between runs; headless pages throttle hidden tabs.
- Hero is Willie's. Pinning the hero changes how it behaves; ask for his reaction before it goes to the real repo.
